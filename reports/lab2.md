- 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？
```
页表项的组成
    [63:54] 保留位：目前未使用的位，保留以供将来扩展。
    [53:28] PPN[2]：物理页帧号的高位部分。
    [27:19] PPN[1]：物理页帧号的中位部分。
    [18:10] PPN[0]：物理页帧号的低位部分，指向物理内存中的 4 KB 页帧。
    [9:8] 保留位：未使用，通常为 0。
    [7] R（Read 可读位）：指示页是否可读。
    [6] W（Write 可写位）：指示页是否可写。
    [5] X（Execute 可执行位）：指示页是否可执行。
    [4] U（User 用户位）：指示页是否可以从用户模式访问。
    [3] G（Global 全局位）：指示页是否是全局的；如果是全局页，则不会在上下文切换时被刷新。
    [2] A（Accessed 访问位）：指示页是否被访问过。
    [1] D（Dirty 脏位）：指示页是否被写入过。
    [0] V（Valid 有效位）：指示页表项是否有效。
标志位的作用
    V（Valid 有效位）：
    表示该页表项是否有效。如果 V=0，表示该页表项无效，无法访问该页。
    R（Read 可读位）：
    指示页是否可读。若 R=1，该页可被读；否则读操作会触发访问异常。
    W（Write 可写位）：
    指示页是否可写。若 W=1，该页可被写入；否则写操作会触发访问异常。
    X（Execute 可执行位）：
    指示页是否可执行。若 X=1，该页可执行；否则执行该页内的代码会触发访问异常。
    U（User 用户位）：
    指示该页是否可从用户模式访问。若 U=1，则该页可以被用户模式访问；若 U=0，则仅限内核模式访问。
    G（Global 全局位）：
    表示该页表项是否全局共享。如果 G=1，则该页在所有上下文中共享，不会在上下文切换时失效；否则，页表刷新可能会使该页失效。
    A（Accessed 访问位）：
    表示该页是否被访问过（读或写）。处理器在访问该页时会自动设置 A=1，操作系统可以通过此位了解哪些页最近被访问过，便于内存管理和页面置换。
    D（Dirty 脏位）：
    表示该页是否被写入过。处理器在写入该页时会自动设置 D=1，操作系统可以根据此位判断页是否需要写回到存储设备。
  ```

缺页
缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

- 请问哪些异常可能是缺页导致的？
```
取指页面错误、加载页面错误、存储页面错误
```

发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
```angular2html
stval 会保存发生异常的虚拟地址、scause 寄存器存储了导致陷入异常的具体原因、sstatus 包含了当前的权限级别、全局中断使能位等状态信息
```

缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

这样做有哪些好处？

```angular2html
节省内存资源、提升启动速度、减少磁盘 I/O
```

其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

```angular2html
10GB 一共是10,737,418,240字节
10GB = 10 * 1024 * 1024 * 1024 bytes = 10,737,418,240 bytes
一个页4kb一个页表可以分配4MB
4KB * 1024 = 4MB
10GB一共需要2,621,440 页就是 2,621,440 个 PTE
10,737,418,240 / 4KB = 2,621,440 页
需要2,560个页表
2,621,440 / 1024 = 2,560
每个页表项占 8 字节就是20KB
2,560 * 8 = 20,480 字节 = 20KB
```

请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

```angular2html
查找虚拟页所在的磁盘位置，将其加载到物理内存中的空闲页帧，一旦页面被加载到内存，操作系统更新页表项，更新完页表后，恢复程序执行
```

缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。

此时页面失效如何表现在页表项(PTE)上？

```angular2html

```

### 双页表与单页表

为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 KPTI )

在单页表情况下，如何更换页表？

```angular2html
将之前保存的用户页表基地址加载到 satp 寄存器中，恢复用户页表基地址
```

单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

```angular2html
在内核空间的PET中的U位为0
```

单页表有何优势？（回答合理即可）

```angular2html
简化设计、减少硬件开销、降低内存碎片
```

双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
